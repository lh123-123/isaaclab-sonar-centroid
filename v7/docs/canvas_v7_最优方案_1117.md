## 一句话结论

**选 E 臂（固定 200 ms 延迟训练）的中段检查点部署 —— 它是唯一「训练条件 = 部署条件」的臂。**

## 一、为什么不是「选分数最高的那个」

这是本次决策最关键的一步。裸分数排名是：

| 臂 | 裸分数 | 训练时是否有延迟 | **200 ms 下实测** |
|---|---:|---|---:|
| C 双尺度 | **11.3 mm**（最好） | ❌ 无 | 未测 |
| B 基线 | 30.8 mm | ❌ 无 | **80.4 mm** |
| E 固定延迟 | 中段 21.8 mm | ✅ **200 ms** | **36.1 mm** |
| D 随机延迟 | 130–165 mm | ✅ 0–200 ms | — |

**裸分数最高的 C 和 B 都是在没有延迟的条件下测的，而实机有 155–201 ms 延迟。**

直接看证据：**B 臂在 200 ms 下从 30.8 mm 崩到 80.4 mm（2.6×）**。C 臂没有延迟训练，没有理由比 B 更好。

所以排序必须按「部署条件」而不是「实验室最好分数」：

> **E 的 36.1 mm 是唯一在真实延迟下测出来的数字。B 的 30.8 mm 在真实延迟下不存在。**

E 相对 B 在同等 200 ms 下是 **2.2×**（36.1 vs 80.4）。这个 2.2× 就是「训练时匹配延迟」的全部价值，也是 `--action_delay_fixed` 这个机制存在的理由。

## 二、五臂结果的重新解读

### A（只收紧奖励 σ=0.05/0.1）—— 已证伪

105k 步崩到 **872 mm**，且崩溃时 `flow_term` 仍有 0.966。机制清楚：锐化 σ 同时拿掉了**全局恢复力**，策略进入「流小 = 分高」的死区解。

**教训**：单独锐化不能解决问题，必须保留宽项做 basin、锐项管最后一毫米 → 这直接催生了 C。

### B（基线 + DR）—— 完整收敛但被奖励饱和锁死

1M 步完整跑完，40 回合 × 2 seed，30.8 mm（95% CI [25.7, 35.9]），peak 56.5 mm（1.83×）。

**但奖励饱和**：`ep_rew_mean` 495 ≈ 98% 满分，5 mm 与 38 mm 只差 **0.5% 回报（约 2.7 分）**，低于 DR 抽样噪声。所以 B 停在这里不是「训练不够」，是**奖励分辨不出好坏**。

### C（双尺度）—— 修好了崩溃，但后期同样退化

宽项 σ 0.2/1.0 保留 basin + 锐项 0.05/0.1 管精度。每步满分 2.55，30 mm 处损失 14 分、870 mm 处损失 152 分 —— 动态范围比 B 大了一个数量级。

100–300k 中位 21.8–23 mm，最好 11.3 mm。**但 367k 时同样出现后期退化。**

### D（随机延迟 0–3 步）—— 失败，原因是部分可观测

374k 停在 130–165 mm 平台，250k 后崩到 300 mm（p90 1376）。

**机制**：每步延迟不同，同一个观测可能对应不同的「已生效动作」，策略无法从观测中区分当前处于哪个延迟 → 本质部分可观测。这不是训练不足，是**信息不足**。

**教训**：延迟要么固定（E），要么给策略显式的延迟状态；随机延迟直接喂进去不行。

### E（固定延迟 3 步 = 200 ms）—— 唯一可部署的

677k，200 ms 下 **36.1 mm**，是 B 同条件（80.4 mm）的 1/2.2。

**但 E 后期也退化**，和 C/D 同一个症状。

### 三臂共同的后期症状（本次最重要的一致观察）

| 量 | 退化前 | 退化后 |
|---|---|---|
| `ep_rew_mean` | 548–550 | **548–550（完全冻结）** |
| `disp_spawn_m` | 22 mm | **39 mm** |

**奖励一分没少，真实指标退了 77%。** 满分 571，奖励停在 96%，而位置退化了。

## 三、根因已定位（源码核实，2026-11-17）

### 证据

`auv_tracking_v7_flow_hover_gsrov_env.py` 的奖励实现：

```python
# GT anchor —— vis_odometry=True 时是 LOGGING-ONLY，不参与奖励
disp_xy = root_pos_w[:, :2] - scene.env_origins[:, :2]
anchor_term = torch.exp(-(d_anchor**2) / sigma_anchor_m**2)

elif vis_odometry:
    # 奖励实际付的是 visodom 估计值
    d_visodom = self._visodom_m().norm(dim=-1)
    position_term      = present * torch.exp(-d_visodom**2 / sigma_visodom_m**2)
    position_fine_term = present * torch.exp(-d_visodom**2 / sigma_visodom_fine_m**2)
```

源码注释自己写明了估计器的失效范围：

> *the estimator itself degrades far out (measured 0.586 m error at a 0.87 m excursion vs 1–6 mm while hovering)*

### 结论

**策略在优化一个会漂的估计器，不是在优化位置。**

- 估计器误差：悬停时 1–6 mm，0.87 m 外扩时 **586 mm**
- 三臂的退化幅度：22 → 39 mm，差 **17 mm**，而同量级的估计器误差约 **24 mm**

误差与要优化的差距**同量级** → 奖励对真实位移的变化不敏感 → `ep_rew_mean` 冻结而 `disp_spawn_m` 继续退化。

**这不是超参数问题，是奖励信号质量问题。所以「再训久一点」不会好转。**

## 四、选定方案

### 4.1 部署

| 项 | 选定 | 依据 |
|---|---|---|
| 策略 | **E 臂 100–300k 区间的检查点**（不用 677k） | 中段 `disp_spawn_m` 最好 21.8 mm，正式评估 36.1 mm @200 ms；677k 已退化 |
| 捕获分辨率 | **960×540** | 模板匹配跳变率 **0%**（640×360 是 0.5%，320×176 是 2.0%）；CV 仅 13.08 ms |
| 模板匹配分辨率 | **960×540（同分辨率）** | 与捕获同分辨率，量化 0.333 px（比训练的 1.0 px 更细，方向安全） |
| 光流 | 320×176，Farneback，参数不变 | 实测四档分辨率光流 RMS 恒为 1.18 px，与分辨率无关 |
| 指令率 | **60 Hz** | 排队均延迟 16.7 → 8.3 ms |
| 串口 | **921600** | 3.5 → 0.5 ms |
| Pi 轮询 | **1 ms** | 省 1 ms |

**不要做的事**（均已实测证伪）：

- ❌ 模板匹配降到 320×176（省 12 ms，但跳变率 0 → **2%**，跳变 28 px ≈ 1 m 处 15 cm 虚假位移）
- ❌ 加置信度门控（跳变帧 PSR 7.6–7.8 vs 正常 8.0–8.2，**无可分性**）
- ❌ 限定模板搜索窗（跳变率从 0–2% 恶化到 **25–30%**，一次锁死永久锁死）
- ❌ CV 多线程（16 核上 0.13 ms，甚至更慢）
- ❌ 640×360（0.5% 跳变率，不值得为了 4 ms 冒这个险）

### 4.2 延迟预算（本条方案下的目标）

| 场景 | 传感器侧 | 执行侧 | 总计 |
|---|---:|---:|---:|
| 当前（720p / 30 Hz） | 44.5 | 156.3 | **201** |
| **本方案（960×540 + 60 Hz + 串口 + 轮询）** | **35.5** | **136.5** | **172** |
| 再加 MJPEG 直通 + 短曝光（需上机确认） | 18.0 | 136.5 | **155** |

**训练死区 200 ms，实机 172 ms（或 155 ms）→ 首次留出 28–45 ms 余量。** 此前 201 ms 是「刚好压线、零余量」。

### 4.3 训练（唯一的根因修复）✅ **已实施并已启动（2026-11-17）**

**已实施的代码改动**（`auv_tracking_v7_flow_hover_gsrov_env.py`）：

| 改动 | 位置 | 原值 → 新值 |
|---|---|---|
| 每台架的校准误差（f_px 尺子） | `dr_visodom_focal_rel_range` | `(1.0, 1.0)` → **`(0.90, 1.10)`** |
| 每台架的校准误差（Z(0) 尺子） | `dr_visodom_range_rel_range` | `(1.0, 1.0)` → **`(0.90, 1.10)`** |
| 每回合尺度残差（新） | `dr_visodom_ep_scale_rel` | 新增，**±5%** |
| 每回合加性偏置（新） | `dr_visodom_bias_m` | 新增，**±20 mm 每轴** |

关键点：**这套 DR 机制原本就存在，只是默认是 `(1.0, 1.0)` 的 no-op**。注释里作者已经写明了动机 ——
"Until now they were exact in sim, so `visodom_err` measured the integrator while pretending the ruler under it was perfect."

**为什么必须加「每回合」的那两项，而不是只开每台架的两个旋钮**

后两者在 `_sample_domain_randomization(per_episode=False)` 里抽取，**只在 `__init__` 抽一次，整轮不变**。
一个整轮恒定的偏置正是策略可以去适应的东西 —— 它要停在哪里让估计读数为零，这个位置整轮都一样。
所以额外补了每回合重抽的尺度残差和加性偏置：

```python
# per_episode 分支，每次 reset 重抽
ep = (torch.rand(n) * 2.0 - 1.0) * self.cfg.dr_visodom_ep_scale_rel
self._visodom_ep_scale[env_ids] = 1.0 + ep
self._visodom_bias[env_ids] = (torch.rand((n, 2)) * 2.0 - 1.0) * self.cfg.dr_visodom_bias_m
self._refresh_visodom_calibration(env_ids)

# _visodom_m() 读的时候加偏置：actor 的 2 个通道、位置奖励、visodom_err_m 看到同一个数
return torch.stack([self._visodom_x, y_m], dim=-1) + self._visodom_bias
```

加性偏置是**最可被利用的那一项**：它让估计在「真值为零」时读出非零偏移，
调好的策略就会停在这个偏移上。零均值、每回合重抽之后，
"把估计驱动到零" 在**真实位移**上重新变成无偏目标。

**没有做的两项（及其原因）**

| 项 | 为什么没做 |
|---|---|
| 逐帧噪声 ±3 mm | 光流积分本身已带噪声，再加一层只是抬高方差，不改变可被利用的偏置 |
| 远距离退化（拟合 0.586 m @ 0.87 m） | 尺度误差已经让误差**随位移线性增长**（Δ = Δpx·Z/f），形状对了；非线性的那部分要等 Phase 3 后看曲线再拟合 |

**本轮训练配置**

```
--task Isaac-AUV-Tracking-Direct-v7-flow-hover
--agent sb3_cfg_entry_point --algorithm SAC
--checkpoint logs/sb3/.../2026-11-16_23-57-37/model_200000_steps.zip   ← E 臂 200k
--action_delay_fixed 3        ← 固定 200 ms 死区，与 Windows 侧实测 201 ms 对齐
--num_envs 8 --headless --flow_method farneback
--max_iterations 100000       ← SAC cfg 的 n_steps=1，× num_envs 8 = 800k 总步数
```

⚠️ 踩坑记录：`--max_iterations` 对 SAC 走的是 `max_iterations × n_steps × num_envs`，
而 SAC cfg 里 `n_steps: 1`，所以传 800000 会变成 6.4M 步。**想跑 800k 就传 100000。**

**判据（必须同时满足，否则视为失败）**

1. `disp_spawn_m` 不再出现 22 → 39 mm 的后期退化（后段 ≤ 前段 × 1.2）
2. `ep_rew_mean` 不再冻结在 548–550
3. 正式评估（40 回合）`disp_spawn_m` ≤ E 的 36.1 mm

⚠️ **预期变化**：加了偏置之后 `ep_rew_mean` 的上限会略低于 571 ——
真值零位置上估计读到 ±28 mm（两轴合成），`position_fine`（σ=0.1 m）因此在真值零处只能拿到 0.925 而不是 1.0，
换算约 **−2.5 分**。所以冻结判据要看「是否仍在 548–550」，不是「是否到 571」。

**结果：这一版修法失败了（2026-11-17，286k 步时停）**

47 个数据点（200k → 286k）：

| 指标 | 表现 |
|---|---|
| `disp_spawn_m` | 前 1/3 均值 **48.8 mm** → 后 1/3 均值 **61.2 mm**（+25%） |
| `ep_rew_mean` | **548 548 549 549 550 549 … 549 548** —— 原样冻结 |
| `visodom_err_m` | 涨到 **28.6–57.8 mm** |

**冻结症状原样重现，而且比 E 臂的 36.1 mm 更差。**

#### 错在哪：我把信噪比弄差了

| 量 | 数值 |
|---|---:|
| 注入的加性偏置 | ±20 mm 每轴 |
| 由此产生的估计器误差 | 15–58 mm |
| **正在被优化的位移本身** | **50–88 mm** |

估计器误差和优化目标同量级 → 奖励里剩下的主要是噪声。
**在估计器误差大于目标精度时，任何奖励层面的 DR 都救不回来。**

#### 第二版修法（实验 2）：把「最后一厘米」从估计器交给模板 —— **发散了，更糟**

环境里本来就有精度够的线索，所以试了把细尺度的权重从噪声估计器挪到模板：

```python
rew_anchor_vis_fine: 0.15 → 0.30   # 模板承担最后一厘米（σ=0.05）
rew_position_fine:   0.15 → 0.00   # 估计器不再在细尺度上计费
```

总分仍是 2.55/571，起点仍是 E 臂 200k，**单变量，可比**。

**结果：61 个数据点（200k → 309k），策略离开 basin 后再没回来。**

| 步数 | `disp_spawn_m` |
|---:|---:|
| 200k – 260k | 稳定在 20–53 mm |
| 268k | **1140 mm** |
| 284k | **2960 mm** |
| 300k | **5130 mm** |
| 307k（停止时）| 3290 mm |

后 1/3 均值 **2844 mm**。`ep_rew_mean` 在 ~250k 见顶 541，之后一路掉到 **421**。

> 注意：`disp_spawn_m` 在源码里**没有 clamp**（直接 `float(d_end.mean())`），所以那些米级数字不是哨兵值，是真的平均位移。

#### 这次失败教了什么：那个"脏"项其实是稳定器

**`sigma_visodom_fine_m = 0.1` 我一直当它是"把噪声线索重复计费"，它其实是唯一承担中等尺度梯度的项。**

| 线索 | σ | 覆盖范围 | 在 50 mm – 0.9 m 这段的作用 |
|---|---:|---|---|
| `anchor_vis_fine` | 0.05 m | ≈10 mm 内 0.30，70 mm 外 ≈0 | 近似阶跃，**无梯度** |
| **`position_fine`** | **0.1 m** | **0 – 100 mm 有效** | **唯一的中间粒度梯度**（已删） |
| `anchor_vis` | 0.2 m | 100–300 mm 较弱 | 偏平 |
| `position` | 1.0 m | 数百 mm 以上 | 偏平 |

删掉 0.1 m 那项之后，**50 mm 到模板 ±0.9 m 窗口边缘之间出现一条盲带**。
一旦越过窗口边缘，每个位置线索都读零，没有任何力把它拉回来 —— 于是漂到 5 m。

**"重复计费"不等于"冗余"。** 这是这次最贵的一课。

#### 结论：奖励不是这个问题的杠杆

| 实验 | 改动 | 起点 | 结果 |
|---|---|---|---|
| E 臂（历史） | 固定 200 ms 延迟 | 全新 | 200 ms 下 36.1 mm（B 臂同条件 80.4）|
| 实验 1（`train_visodom_dr.log`）| + visodom 校准/加性偏置 DR | E 200k → 286k | ❌ 退化重现：48.8 → 61.2 mm |
| 实验 2（`train_template_fine.log`）| 细尺度权重改由模板承担 | E 200k → 309k | ❌ **发散：2.8–5.1 m** |

**两次修法都比不改更差。截至 2026-11-17 全部回退，代码已回到 E 臂的干净条件：**

| 项 | 回退后 |
|---|---|
| `rew_anchor_vis_fine` | `0.30` → **`0.15`** |
| `rew_position_fine` | `0.00` → **`0.15`** |
| `dr_visodom_focal_rel_range` | `(0.90, 1.10)` → **`(1.0, 1.0)`** |
| `dr_visodom_range_rel_range` | `(0.90, 1.10)` → **`(1.0, 1.0)`** |
| `dr_visodom_ep_scale_rel` | `0.05` → **`0.0`** |
| `dr_visodom_bias_m` | `0.020` → **`0.0`** |

满分 2.55/571，visodom DR 全部 no-op —— **与 E 臂逐位一致，不残留任何实验痕迹**。
（新增的每回合抽样代码路径保留，只在 no-op 值时抽到 `1.0 / 0.0`，不改变行为。）

由此做出的判断：

1. **停止在奖励上做文章。** 后期 22 → 39 mm 的退化是个小问题，代价远小于把它治成 3 m 的漂移。
2. **E 臂 100–300k 的检查点仍是最好的部署候选**（中段 21.8 mm，正式评估 36.1 mm @200 ms）。
3. **论文定位彻底转「线索冗余 / 优雅退化」**，不再碰任何精度叙事。

**这条判据现在改写成**：任何后续改动，先验证它在 0–1 m 全量程内**不会破坏 basin**；
只盯着 20–40 mm 那一小段的改动，一律先做短跑（≤150k 步）+ 看 `peak_m`，不许直接上长跑。

### 4.4 论文定位

三条主张的当前状态（截至 11-17）：

| 主张 | 状态 | 硬数据 |
|---|---|---|
| RL 比经典控制更准 | ❌ **不成立** | 30.8 mm vs **LQR 3.3 mm**（0.30 m/s），差 9 倍 |
| RL 抗洋流突变 | ❌ **不成立** | LQR 突变下无退化（1.7 mm） |
| RL 抗线索丢失 / 优雅退化 | ⏳ **唯一还站得住的** | 基线峰值退化：P 1.56× / PID 1.81× / LQR **4.43×**，RL **未测** |

**选定框架 A（冗余线索 / 优雅退化）。** 放弃「比 LQR 更准」的叙事 —— 数据不支持，碰了就是硬伤。

框架 A 的叙事骨架：**三条冗余的视觉线索（光流 / 首帧模板 / 视觉里程计）在失效区间上互补**，单条线索缺失时系统优雅退化，而不是像单一线索的 LQR 那样崩 4.43×。

**但这个框架目前还缺最关键的一块证据：RL 侧的线索丢失测试没做。**

### 4.5 验证实验（决定论文能不能写）

| **线索丢失消融** | 用 `ablate_flow` / `ablate_template` / `ablate_visodom` 分别清零，测峰值退化倍数 | RL < **1.56×**（P 的水平）→ 主张成立；> 2× → 主张弱化；> 4.43× → 主张全灭 |

## 五、执行顺序

#### 为什么只保留分辨率

**分辨率的收益最纯粹、风险为零。** 实测四档分辨率的光流 RMS 恒为 1.18 px（信号与分辨率无关，不需要重训），
而模板匹配跳变率在 960×540 及以上是 **0%**，到 640×360 才出现 0.5%、320×176 是 2.0%。
所以 960×540 是"零跳变前提下最快"的那一档，纯粹是拿掉风险，不引入任何新变量。

**其余三项都动了运行时行为，而且各有前置依赖：**

| 回退项 | 为什么不先动 |
|---|---|
| 波特率 921600 | **必须配套改飞控 `SERIAL0_BAUD=921` 并重新上电**，否则链路直接不通。仓库里 11 份参数快照全部是 `115`，一处都没改过。这是上机动作，不是代码动作。 |
| 指令率 60 Hz | 飞控 PWM 仍是 50 Hz，60 Hz 只省排队延迟、不提高执行器带宽；而且它会改变指令时序，得跟控制环一起验证。 |
| 轮询 1 ms | 单独改收益只有 1 ms，不值得在没做全链路埋点前先动。 |

**结论**：先把分辨率这个零风险的改动落地并实测，其余三项等上机、等埋点，**一次只引入一个变量**。
原来那套"四项一起上"的方案违反了这个项目自己总结的 A/B/C 臂方法学。

#### 由此解除的风险

原方案里那条 ⛔ **"飞控 `SERIAL0_BAUD` 不改则链路不通"** 随波特率回退一并解除 —— Pi 侧和飞控侧现在都是 `115200`，链路保持原样。

#### 延迟收益（回退后的实际预期）

| 项 | 保留/回退 | 收益 |
|---|---|---:|
| 960×540 + 同分辨率匹配 | ✅ 保留 | **−7.3 ms**（CV 20.41 → 13.08 ms） |
| 跳变率 | ✅ 保留 | 0.5% → **0%**（风险归零）|
| 指令率 60 Hz | ↩️ 回退 | 0（原 −8.4）|
| 波特率 921600 | ↩️ 回退 | 0（原 −3.0）|
| 轮询 1 ms | ↩️ 回退 | 0（原 −1.0）|
| **合计** | | **−7.3 ms，总延迟 201 → ~194 ms** |

**判据**：埋点实测总延迟 ≤ 195 ms；模板匹配 200 帧零跳变。

> 要拿到原来的 172 ms，仍需把回退的三项做完 —— 它们是 Phase 2 的入口条件，不是被否决，是**被推迟**。

## 六、风险与失败条件

| 风险 | 后果 | 应对 |
|---|---|---|
| Phase 4 显示 RL 线索丢失也退化 >2× | **三条主张全灭**，只能改写「系统集成 / 估计器」框架 | 提前准备框架 B 的素材 |
| visodom DR 注入后仍后期退化 | 根因判断错误，需重新诊断 | 退回检查 `present` 门控与 `sigma` 的交互 |
| 相机不支持手动曝光 | Phase 2 只能拿到 MJPEG 直通的 15 ms | 目标调整为 160 ms 而非 155 ms |
| ESC 不支持 DShot | 少省 7.5 ms | 保持 PWM 50 Hz，接受 155–160 ms |
| 推进器实测 > 150 ms | 整链地板抬高，200 ms 死区不够 | 需重新训练，死区设到实测值 |

**硬约束**：E 的 36.1 mm 与 LQR 3.3 mm 差 11 倍。任何「更准」的表述都不能出现在论文或汇报里。
