# 数据需求清单：视觉目标悬停 DRL（基于 ROV 实艇）

本清单把「DRL 训练所需的全部数据」分成两类：
- **已有**：交接包 `source/isaaclab/isaaclab/rov/` 已提供，可直接用于建模/训练。
- **缺口**：必须由你方补充（测量/标定/记录），否则训练出的策略无法迁移到实艇。

> 前提：我们训练的是「视觉悬停」（station keeping via 全局光流零化），
> 而非比赛任务本身，也不依赖特定目标物体。比赛规则/场地仅作场地尺寸参考。

## 1. 已有数据（可直接用）

### 1.1 机体几何与推进布局
- **STEP 模型**：`机械与电路/Robocup-ROV.STEP`（整体 ROV 几何，含推进器/舵机/夹爪）。
- **推进器编号（俯视，机头向前）**：左上1、右上2、左下3、右下4（斜推，前后/侧移/偏航）；中左上5、中右上6、中左下7、中右下8（升降/姿态）。
- **机架类型**：`FRAME_CONFIG=2`（Vectored 6DOF）。
- **推进器方向签名**：`MOT_1..8_DIRECTION = [+1,-1,-1,+1,+1,-1,-1,+1]`。
- **SERVO 功能映射**：`SERVO1..8_FUNCTION = [34,33,36,35,38,37,40,39]`；`MOT_H_REV=1`（水平侧移/偏航符号修正）。
- **三路舵机**：SERVO9 夹爪、SERVO10 上下、SERVO11 旋转；`FUNCTION=0`（Disabled，桥接直发 PWM）。

### 1.2 相机
- **型号**：Generic USB UVC，MJPEG 输入转 H.264。
- **分辨率/帧率**：1920×1080 @ 30 fps（训练建议先用 720p/640×480 降算力）。
- **焦距**：水下手动焦距 224/1023（透明球罩更换后标定，换相机/球罩/水质必须重测）。
- **安装**：相机直装，无 180° 旋转（仿真与实机一致；若实机倒装，在软件层 flip，不在仿真里旋转）。
- **FOV**：**已实测 81.646° HFOV**（水下棋盘格标定，见下）；早期"按 90° 建模"的说法作废 —— 那是按 `--hfov 90` 反解焦距得到的，比实机宽 8.4°，仿真已改为 81.65°。
- **到 PC 延迟**：未知，需单独测量（采集→编码→网络→解码）。

### 1.3 控制与动力约束
- **PWM 端点**：`MOT_PWM_MIN/MAX = 1100/1900` µs；启转补偿 50 µs；死区 ~1%。
- **电流保护**：`MOT_BAT_CURR_MAX = 20 A`，时间常数 0.5 s。
- **定深限幅**：`MOT_DH_MAX = 25%`。
- **控制链**：手柄 → Windows 桥接 → UDP → 树莓派 → Pixhawk/ArduSub → 8 推进器/3 舵机。
- **动作尺度（训练用）**：surge `a_v` ∈ [-1,1] m/s；yaw `a_w` × 0.5 rad/s（v5/v4-cam 经验）。
- **无水平定位**：没有 GPS/USBL，纯视觉+IMU+深度计。

### 1.4 传感器与飞控
- **IMU/姿态**：Pixhawk1 融合姿态（横滚/俯仰/航向），航向来自飞控融合。
- **深度**：压力计，水面零点需校准。
- **电压/电流计**：`BATT_MONITOR=4`，`VOLT_MULT=10.1`，`AMP_PERVLT=17`，`OFFSET=0`（换电流计必须重新标定）。
- **失控保护**：`FS_PILOT_INPUT=2s`，`FS_GCS=5s`。
- **稳姿/定深闭环**：`ROV_T_ERR=0.5°`，水平目标 `ROV_LVL_R/P = 1.36°/0.62°`。

### 1.5 环境与场地
- **泳池**：7.5 m × 3.5 m，水深 ~1.3 m（训练仿真场景尺寸）。
- **场景纹理参考**：悬停不依赖目标物体，只需场景有足够纹理（池底、标记、自然特征）；高尔夫球/环形零件仅作比赛道具参考，训练场景用纹理化底板/标记。
- **网络/IP**：电脑 192.168.1.4，树莓派 192.168.1.3（部署用，训练不需）。

### 1.6 历史参考代码（可借鉴算法）
- `历史参考_不运行/ROV_PC_GUI_202608/`：`thrust_allocator.py`（推力分配）、`attitude_math.py`（姿态转换）、`depth_raw_capture.py`、`imu_depth_combined.py`、`Heading_Control.py`、`yaw_feedback.py`、`controller.py`。
- 这些是 PC 端旧 GUI 的算法，可作为 thrust allocator 与姿态数学的参考，**不直接运行**。

## 3. 关键决策点（需要你拍板）

1. **仿真用 WarpAUV 代理还是建真实 ROV 模型？** —— ✅ **已定：走 B**
   - A：用现有 WarpAUV（BlueROV-like）+ 域随机化 → 快，但动力学/外观与实艇差异大。
   - B：从 STEP 建 URDF/USD（质量/惯量/推进器坐标）→ 精确，但工作量大。
   - **现状**：v7 已切换到 GS-ROV 实体船体（`thruster_layout="gsrov8"`，4 垂推 + 4 横推，
     13.15 kg / 排水 12.95 L / 惯量由 CAD 包围盒估算），质量、COM/COB、推进器布局均已按 CAD 落地。
     仍待实测的是**推力–PWM 曲线**与**相机外参**。

2. **场景纹理定义**：用什么纹理？建议高对比度纹理化底板 + 随机标记，便于 flow 与门控。

3. **训练场景维度**：仅 3DOF（surge+yaw+depth hold）还是 6DOF？建议先 3DOF（与 v5 一致），再扩展。

4. **流体建模深度**：是否建模系缆？建议先忽略系缆跑通，再加系缆扰动做鲁棒性。

## 5. 一句话结论

已有数据已足以支撑「几何/质量特性/相机内参」层面的建模 —— 这四项均已落地：GS-ROV CAD 船体与 8 推进器布局、质量 13.15 kg / 排水 12.95 L / COM-COB 偏向、以及水下实测相机内参（RMS 0.543 px，HFOV 81.646°，仿真已按 81.65° 对齐）。

**剩余的最大缺口按影响排序**：

1. **水面倒影建模**（P0 #10b）—— 实机画面上部约 52% 是水面倒影而非景物，而 v7 的光流、纹理掩码、首帧模板都假设整幅画面是静态场景。这一项没有被域随机化覆盖，**可能动摇方法前提，优先处理**。
2. **推力–PWM 曲线**（P0 #6）—— 现在用的是厂家数据表（19.613 N 正 / 17.652 N 反），不是实测。
3. **相机外参**（P0 #10）—— 仿真按机头前方朝 +X 假设，未经确认。
4. **悬停场景的纹理规格**（P1 #22）。

"先用 WarpAUV 代理跑通流程"这一阶段已经结束，v7 跑在真实船体参数上。
