## 2. 架构与数据方向

`飞智八爪鱼5手柄 → Windows 桥接/状态窗 → UDP → 树莓派 rov-mavlink.service → Pixhawk1/ArduSub → 8推进器/3舵机`。

飞控负责传感器融合、机体坐标系混控、姿态/定深闭环和保护；QGC 负责遥测、参数、传感器校准、原生罗盘及视频显示。桥接将飞控遥测同时送到 QGC 的 UDP 14550 和电脑状态窗的 14551。USB 摄像头在树莓派编码成 H.264 RTP，向电脑 UDP 5600 发送。QGC Fly 比赛卡从电脑本机 `127.0.0.1:18765/status` 只读抓取额外状态，不接管飞控。没有水平定位传感器，**不是世界坐标定点**；左杆“向前”始终是机体前方。

现有配置示例：电脑有线 `192.168.1.4`，树莓派 `192.168.1.3`；飞控 USB 由 `/dev/serial/by-id/usb-ArduPilot_Pixhawk1_3B0042000450325635393420-if00` 指定，摄像头由 `/dev/v4l/by-id/usb-Generic_USB_camera_200901010001-video-index0` 指定。**这两个 by-id 仅适用于原设备**，换飞控/摄像头后必须重新识别，不按 USB 插口位置猜测。

## 3. 另一台 Windows 电脑：不接动力的复现步骤

1. 把整个交接文件夹复制到短路径，例如 `D:\ROV_20261021`。以后不要移动该目录：QGC 自定义 QML 使用安装后的绝对路径。在交接文件夹根目录运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\ROV_preflight_readonly.ps1`，先核对文件哈希、Python 和 QGC 路径。它只读本机文件，不访问设备。
2. 安装 **QGroundControl 5.1.4** 和 **Python 3.10 或更新版本**（建议在新机选用同一个已测试的 3.11/3.12 环境，再实际跑测试）。现机此终端的默认 `python/pythonw` 指向 3.8.15，**不兼容**代码中的 `float | None` 类型语法；2026-10-21 用它运行 `--check` 已在导入时失败。先用 `python --version`、`where.exe python`、`where.exe pythonw` 确认执行器，不能凭已安装 Python 就假定 BAT 用的是它。将 `电脑端/pc_gamepad_bridge/launch_settings.json` 中的 `qgc_path` 改为**新电脑真实 QGroundControl.exe 路径**。不要沿用 `D:/QGroundControl/bin/QGroundControl.exe`，除非新机确实如此。
3. 在 PowerShell 进入 `电脑端/pc_gamepad_bridge`，创建独立虚拟环境并安装 `requirements.txt`：

   ```powershell
   python -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   .\.venv\Scripts\python.exe launch_competition.py --check
   ```

   上述 `python` 必须先确认是 3.10+；若默认仍是 3.8，请用 3.10+ 的**完整可执行文件路径**创建虚拟环境。原 `比赛启动.bat` 调用系统 `pythonw`，不会自动用上述虚拟环境。可把 `电脑端/比赛启动.bat` 中的 `pythonw` 改成 `"%~dp0pc_gamepad_bridge\.venv\Scripts\pythonw.exe"`；只改新机解压副本，不改原机。`--check` 应报告 `startup: monitor only`；它不检查实机链路。
4. 按新网络修改 `launch_settings.json` 中 `pi_ip`。保留端口 14550（QGC）、14551（状态窗）和 5600（视频），除非整套网络配置一起调整。电脑 IP 若非 `192.168.1.4`，树莓派端 `rov-mavlink.service` 的 `--gcs-ip`、`video_profile.json` 的 `pc_ip` 和可能的防火墙规则也要同步修改。新机允许这些 UDP 入站端口；不要对公网开放本机状态 HTTP。
5. 先关闭 QGC/状态窗，进入 `电脑端` 运行 `启用QGC比赛仪表.bat`。它只改当前 Windows 用户的 QGC INI 仪表字段并自动备份，QML 指向解压目录；失败时查看命令行信息。之后启动 QGC，Fly 右下角应见比赛卡和 QGC 原生圆形罗盘。恢复可用同目录 `恢复QGC原仪表.bat`，必须先退出 QGC。
6. 在 QGC 设置视频源为 UDP H.264、端口 5600；启用低延迟选项如该版界面提供。选择适合显示器的画面铺满方式；视频分辨率由树莓派配置决定，而非仅改变 QGC 窗口。QGC 的 Joystick **取消 Enable**，避免它与专用手柄桥接同时发控制。
7. 双击 `电脑端/比赛启动.bat`。默认只是监视；不得因程序打开就认为可操纵或可解锁。小状态窗必须在后台持续运行，比赛时可以最小化；仅开 QGC 不会自动启动专用手柄桥接。

离线核验：用上面的虚拟环境 Python 运行 `launch_competition.py --check`，再在 `电脑端/pc_gamepad_bridge` 运行 `python -m unittest discover -p "test_*.py"`。这次打包过程中因本机默认 Python 3.8 不兼容，**没有得到当前包的完整离线测试通过结论**；另一台电脑必须自行跑通。这些测试通过仍不等于新机 HID、QGC 视频、实艇方向和水下闭环验收。八爪鱼5需在飞智空间站允许第三方应用接管映射；未接手柄时面板会继续等待。

## 4. 树莓派复现：先只读识别，再部署

原机服务用户为 `liang`，目录 `/home/liang/underwater_robot`。新机在树莓派上先只读核对：`hostname -I`、`ls -l /dev/serial/by-id/`、`ls -l /dev/v4l/by-id/`、`systemctl cat rov-mavlink.service rov-video.service`、`python3 --version`、`command -v ffmpeg`。如果任何设备路径、用户名、网络地址不同，先改服务模板和配置。不要让 QGC、脚本及其他服务同时独占飞控串口。

将 `树莓派端/pi_competition` 中的脚本和配置复制到新 Pi 的项目目录；安装 `ffmpeg`、`v4l-utils`、`python3-pymavlink` 等依赖，以实机发行版包名为准。配置 `rov-mavlink.service` 中的串口 by-id、115200 波特率、电脑 IP；配置 `video_profile.json` 中摄像头 by-id 与电脑 IP。服务模板可作为起点，**不能直接覆盖已有服务或在运行中替换**。备份现有文件/服务后，在飞控上锁、动力断开时有序安装并检查 `systemctl status`、`journalctl`。先确认双路遥测新鲜、视频稳定，再允许手柄控制。

目前视频配置快照：USB/UVC MJPEG 输入，1920×1080、30 fps、目标 8 Mbps，180° 翻转、`mild` 增强、固定水下焦距 224/1023；224 是更换透明球罩后在一次水下静态场景扫描得到的值，**换相机、球罩、目标距离或水质必须重新测清晰度**。自动对焦控制不提供可靠实时镜片位置回读，不能把手动焦距控件读值冒充实时自动焦距。视频录制或 CPU/温度/网络压力可能使延迟增大；不宣称本包具有已实测的固定端到端延迟。

## 5. 飞控与实体映射

原实艇为 Pixhawk1/ArduSub 定制固件、`FRAME_CONFIG=2`（Vectored 6DOF）。从俯视机头向前看，物理推进器编号为：左上1、右上2、左下3、右下4；中间左上5、右上6、左下7、右下8。1–4 负责前后/侧移/偏航的斜推，5–8 负责升降/姿态；这**不是**仅凭机架图就能断言接线正确。历史读回的 `MOT_1..8_DIRECTION` 为 `+1,-1,-1,+1,+1,-1,-1,+1`，`SERVO1..8_FUNCTION` 依次为 `34,33,36,35,38,37,40,39`；`MOT_H_REV=1` 处理这台机体实测的水平侧移/偏航符号。换安装方式必须逐台低输出核对推水方向，再决定是否改映射，不能复制方向参数后直接下水。

三路机械臂：`SERVO9` 夹爪开合、`SERVO10` 上下、`SERVO11` 末端旋转；`SERVO9/10/11_FUNCTION=0`（Disabled）让桥接直接发送 `MAV_CMD_DO_SET_SERVO`。Disabled 不等于端口无电。控制配置目前的夹爪 610–1350 µs、上下 500–2500 µs、旋转 1000–2060 µs 是这台机体的**软件目标范围**；机械端点要按新舵机逐步测，不能先把 500/2500 全行程套上。历史飞控读回的 SERVO9–11 MIN/TRIM/MAX 仍是 1100/1500/1900，不能把它们和桥接直控目标范围混为一谈。

## 6. 日常操作与手柄键位

面板启动后确认飞控心跳/上锁/模式、手柄连接、摇杆与扳机全部归中；点“开启手柄控制”。它不会自动解锁；A 许可单独设置。QGC Joystick 保持关闭。A 解锁、B 立即请求上锁；X 独立切换定深、Y 独立切换稳姿，两者均默认关，可以组合。手柄前后、侧移和偏航是机体坐标命令；稳姿开启时飞控用原生姿态横滚/俯仰回平，偏航松杆锁当时飞控航向；定深开启时扳机实际回到中位才抓取当前飞控深度为目标。惯性下仍可能继续运动一段距离，不能理解为“立即停住”。

| 输入 | 现用动作 |
|---|---|
| 左摇杆 | 前后、左右平移 |
| 右摇杆 | 偏航、俯仰；横滚无手动输入 |
| RT / LT | 上升 / 下潜；升降独立档位 |
| 左菜单 / 右菜单 | 循环摇杆档位 / 升降档位，均为 40% ↔ 100% |
| LB | 两组档位恢复已保存的共同默认值，当前 40% |
| X / Y | 定深开关 / 稳姿开关，实际状态以飞控回传为准 |
| RB、M3/M4 | 夹爪快切、按住慢开/慢合 |
| M1/M2、LM/RM | 上下舵机慢调、末端旋转慢调 |
| 十字上/下 | 云台预设角度逐档切换 |
| 十字左/右 | 云台快捷角度 / 上下舵机复位脉冲；**当前 JSON 是 -40° / 1200 µs**，不是早期说明里的 -20° / 920 µs |

档位 40/100% 是**驾驶输入增益**，不是电机最大推力比例。QGC `MOT_PWM_MIN/MAX` 和控制器限幅仍决定输出可达范围。状态窗目标角度、夹爪“下次动作”不是机械位置反馈。

## 7. 所有参数怎样调：先选层级，再保存、读回

每次调参先保存当前**实机完整参数快照**，记录日期、固件标识、飞控 UID、改前/改后数值及水中现象。QGC：Vehicle Setup/Parameters → 搜索完整参数名 → 修改**单项** → 等写入确认 → Refresh/重新读回 → 必要时重启飞控 → 再读回。需要调 PID 时一次只动同一回路的一项、小步调整，先低档短时水测；禁止同时改电机方向、限幅和 PID 后无法归因。参数文件在 QGC 默认目录 `Documents\QGroundControl\Parameters`；旧 `.params` 只是快照，不能盲目全量导入。

|---|---|---|
| 手柄死区、响应、档位、云台快捷目标、舵机软件范围 | `电脑端/pc_gamepad_bridge/controller_profile.json` 或状态窗对应设置，保存后重开程序/按界面提示 | 摇杆死区 4%、扳机 3%；两组 40/100%，默认 40%；当前快捷目标 -40°/1200 µs。改这里**不修改飞控 PID 或 PWM 硬件限幅** |

## 9. 安全验收与故障判断

先软件离线自检 → 无动力连通 QGC/状态窗/视频 → 对照参数及传感器 → 动力隔离下确认每一路输出逻辑 → 固定机体于水中低档逐台验推水方向 → 短时水平/升降 → 单独稳姿/定深 → 组合模式与负载 → 断链和急停演练。任何一步不通过，停止进入下一步。既往出现过“只在推进器工作时树莓派红灯熄灭、QGC/视频掉线”，属于供电链严重风险：优先查降压模块在动态负载下的 Pi 5 V 端电压、接插件压降、共地、保险/线径和漏水；软件降码率/改 PID 不能代替电源修复。若控制链、视频或电流遥测失效，先安全停机，不为排障反复满推。

QGC 告警与处理边界：`Compass performance degraded`、`EKF ... MAG ... yaw re-aligned` 表示航向可信度需查磁干扰/校准；`Lost manual control` 表示手柄控制链中断，不能假定 B 上锁命令仍能送达；飞控电流长期 0 A 但推进器确实转动，先查电流计、线束和电池监测参数，**不要依赖 20 A 软件限流**。视频“固定慢半秒到一秒”需要单独量取端到端延迟，检查采集→编码→网络→QGC 解码/录制链，不把编码端 30 fps 等同低延迟。
