# 八爪鱼5比赛控制方案（2026-10-04双档位版）

本版取代此前互相矛盾的三轴独立锁方案。PC负责输入、档位、云台预设和模式请求；
树莓派转发MAVLink；Pixhawk运行ArduSub姿态/深度闭环与8推进器混控。
旧系统的PID、推进器分配和直接PWM输出不接入此控制链。

## 最终键位

| 操作 | 功能 |
|---|---|
| 左摇杆前后／左右 | 前进后退／左右平移；保留斜向运动 |
| RT／LT | 线性上浮／下潜；同时按时取差值 |
| 右摇杆左右／上下 | 左右转向／机体俯仰 |
| A | 请求解锁；仅实机发送且启用 `--allow-arm` 时放行 |
| B | 请求立即上锁；优先于其他按键，运动输入同时归中 |
| X | 独立开／关定深，保留姿态状态；仅定深需新版固件 |
| Y | 独立开／关姿态，保留定深状态；仅定深需新版固件 |
| 左菜单（View，HID按钮4） | 独立循环摇杆操纵增益：40／100% |
| 右菜单（Menu，HID按钮6） | 独立循环LT/RT升潜操纵增益：40／100% |
| LB | 两组一起恢复已保存的共同默认档位；当前默认40% |
| RB | 在夹爪已保存的闭合／张开端点间快速切换；面板显示下一次动作 |
| 十字上／下 | 云台抬高／压低一档 |
| 十字左 | 云台快捷角度（可设，默认-20°） |
| 十字右 | 上下舵机一键复位（可设，默认920µs） |
| M1／M2 | 按住夹爪角度慢上／慢下，松开停止 |
| M3／M4 | 按住夹爪慢开／慢合，松开停止步进 |
| LM／RM | 按住末端慢速逆时针／顺时针，松开停止 |
| L3、R3、Home | 不分配比赛功能 |

十字键不切换飞行模式、不影响定深。斜按同时出现两个方向时忽略该次动作，松开后重新按。
移除原L3/R3云台功能，避免按压运动摇杆时误触。六个拓展键仍由原始HID独立读取，
不需要在飞智空间站复用普通按键。慢速夹爪操作优先于RB；相反方向同时按下时停止步进。

## 模式与手感

- STABILIZE：飞控稳定姿态，升潜由扳机操作。
- ALT_HOLD：增加定深。扳机调整深度，松开后在新深度附近保持，不需反复退出定深。
- MANUAL：姿态/定深都关闭，右摇杆直接控制偏航/俯仰推力，松杆停止指令但不自动回平。
- DEPTH_ONLY（自定义22，待编译/烧录）：压力闭环定深，姿态手动，无自动回平/航向保持。

右摇杆俯仰在这些模式中是倾角指令，回中时目标回到0°水平，不是记住任意俯仰角。
人工横滚输入固定为0，由飞控修正横滚。偏航有输入时转向，回中后由飞控航向控制接手。

2026-10-04 离线增强按此规则加入平顺回平、模式切换目标保持和姿态优先分配，
没有添加“保持最后俯仰/横滚倾角”。详见[控制方案与验收](firmware/控制方案与验收.md)。
增强源码尚未完整编译/烧录，标准模式原本的回平规则不依赖增强参数。
仍需有效的航向估计、传感器校准及水下调参。取消独立三轴锁及“清除三锁”。

X/Y根据最新飞控模式独立切换；有未完成的模式请求时先等回传，再按下一次。
X/Y同时按下时仅Y生效。缺失或过期回传时不发送模式请求；超时或拒绝时显示失败，
不自动重复。只有飞控心跳回报目标模式才显示成功。旧固件未回传ROV_DONLY=1时，
需要模式22的请求直接提示需新固件。不会自动用ALT_HOLD代替仅定深。
默认开启手柄控制后先在上锁、归中状态请求MANUAL，两项关闭；默认重置失败会阻止
正常操纵，不能直接沿用上次的稳定/定深状态。详见独立模式与安装校正_20261004.md。

I²C只是接口。外部水压计须被ArduSub识别、数据健康、入水深度变化正确，
再确认ALT_HOLD能进入。PC不独立判断水压计健康，由飞控执行模式检查；
失败时查看QGC消息，不能绕过检查。

没有水平定位/测速时，不能自动定点或保证斜向航迹绝对笔直，水流和惯性造成的水平漂移
仍需人工修正。定深与姿态稳定不替代位置保持。

## 操纵与舵机

左右摇杆保留4%圆形死区、柔和正方向辅助：距主轴8°内消除小串轴，
8°～18°平滑恢复，18°以外保留斜向输入。扳机死区3%，死区外连续线性。
摇杆档统一缩放前后、左右平移、偏航和俯仰；升潜档只缩放LT/RT，不影响摇杆。
两组循环都是40→100→40%，一次按下只切换一次；同时按LB和菜单时LB复位优先。
“默认运动档位设置 · LB复位”可保存共同默认值，保存不改变当前两组档位；按LB或下次启动时生效。
默认值保存在PC的controller_profile.json，不需重新部署树莓派，也不需为改变默认档重新导入QGC参数。

“40%档”是PC操纵输入增益，不是实测速度40%或电机总功率上限。
飞控JS_GAIN等还可能继续缩放输入；姿态/深度修正推力不被PC档位直接封顶。
低档不能作为推进器可以在岸上随意转动的依据。

云台上下档位：-80°／-45°／-20°／0°／+20°。GUI显示目标角度，非实际角度；
十字左与右的目标在状态窗“十字快捷目标”中设置并保存到电脑端配置，不需重新烧录飞控。
安装方向、机械行程和到位时间仍需验证。

| 接口 | 功能 | 当前假定 |
|---|---|---|
| MAIN1～8 | Motor2/1/4/3/6/5/8/7 | 保留实体编号与插头，左右输出功能映射互换 |
| AUX1 / SERVO9 | Disabled + PC直接PWM | 唯一末端夹爪开合 |
| AUX2 / SERVO10 | Disabled + PC直接PWM | 夹爪角度上下 |
| AUX3 / SERVO11 | Disabled + PC直接PWM | 末端旋转 |
| AUX4 / SERVO12 | Mount1Pitch | 摄像头云台 |

实体推进器编号与QGC标准图左右相反，但保留现有MAIN1～8插头位置。输出功能映射为：

| 3 左下 | 3 | Motor4 | 4 |

QGC机架示意图本身不会镜像；上述映射让标准Vectored_6DOF混控输出到正确的实体位置。
方向反转仍需逐路短测后单独确定，不能由位置映射推断。

机械臂改为PC直接发送目标PWM：按住时按时间以约100µs/s连续变化，不再依赖
MANUAL_CONTROL帧率重复飞控按钮。实机确认：M3增加PWM为张开，M4减少PWM为闭合；
M1减小PWM为夹爪上抬，M2增加PWM为下压；LM减小PWM为逆时针，RM增加PWM为顺时针。
舵机资料确认控制周期为20ms（50Hz），500／1000／1500／2000／2500µs分别约对应
0／45／90／135／180°。程序保护范围为500～2500µs，约100µs/s即约9°/s。
RB在已保存的闭合／张开端点间切换；M3/M4微调后，程序仍记录并显示下一次动作。
500/2500只是绝对允许范围，并非必须使用的实际端点。比赛小窗口可打开“设置舵机实际范围”，
分别设置三路舵机的最小/最大值；RB自动使用夹爪开合所保存的最小/最大值。
如果500µs时机构仍夹不紧，应在1500µs中位重新安装舵盘或调整连杆，不能继续降低脉宽。
任何端点都须先在无负载或可立即断电条件下验证不顶死，再作为比赛设置。

## 文件与启用步骤

推荐日常入口已补齐：双击上级目录`比赛启动.bat`打开QGC和小型状态窗，启动只监视。
完整启动/视频部署步骤见上级`启动与摄像头说明.md`。以下命令行方式仍可单独使用，
不要与一键入口同时运行。普通QGC图标不会启动桥接。

1. `controller_profile.json`是键位配置，两个PC入口共用。
2. QGC导入`C:\Users\15057\Documents\QGroundControl\Parameters\ROV比赛参数_最新版.params`；
   工程目录的同内容文件作为备份，`.param`是Mission Planner备用。
   新增清零BTN2/3/9/11/12/13/14，防止PC本地按键被飞控重复执行。
   本版把BTN10/15～20设为0，并把SERVO9/10/11_FUNCTION设为0（Disabled），由PC直接控制；
   不改电机布局、推进器PWM端点、PID或失控保护。导入后必须重启飞控。
3. 将本地`pi_competition/rov_mavlink_bridge.py`更新到树莓派服务实际使用的脚本位置，
   在上锁且停止实机发送时重启服务。本次尚未部署。部署前用
   `systemctl cat rov-mavlink.service`确认实际脚本路径。
4. 新版Pi桥把飞控数据同时发给电脑UDP14550（QGC）与14551（手柄程序）。
   PC默认监听14551，Windows防火墙须允许接收。
   旧Pi桥没有14551回传，本版PC会显示模式未知并阻止正常控制流，不能直接用于比赛。
5. 双击`start_panel_monitor.bat`先核对按键。监视模式不发控制、不收遥测，不能验证定深。
6. 实机只选GUI或命令行一个入口，QGC Joystick取消Enable。
   `py .\rov_control_panel.py --send`默认仍屏蔽A；
   完成实机验收后另加`--allow-arm`才放行解锁。
   程序启动不自动解锁或切模式。先看实际回传，再按Y确认STABILIZE。

手柄输入超过0.25秒不更新或飞控心跳超过3秒不更新时，停止正常MANUAL_CONTROL流。
B在手柄有效时仍允许发送上锁请求；断网不能保证送达。须配置并断链验证飞控
Pilot Control失控保护；QGC仍在线时，不能只依赖GCS心跳失控保护。

QGC数字按键格未修改，中文功能由本地面板显示。QGC用于参数、遥测、告警和模式复核。
现已准备USB摄像头到QGC的H.264推流脚本，尚未部署及验收；视觉识别仍未实现。

本地测试验证按钮冲突、输入和模式确认逻辑，不能证明水下稳定。
传感器、逐路推力、舵机限位和断链保护验证后，再低增益入水验证姿态、定深和斜向运动。
解锁后即使摇杆回中，飞控也可能为稳定姿态输出推力。
