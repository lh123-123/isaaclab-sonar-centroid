# 推进器逐个测试

本功能仅在Windows电脑上运行，不需要更新树莓派、不需要重新导入参数。
从原来的`比赛启动.bat`打开ROV状态窗，点击“推进器逐个测试”。

2026-10-04：运动启转现分“前后/升潜”“侧移/转向”“俯仰/横滚”三组，各显示四项。
切换组先停止输出，不启动新动作；抬头/低头/倾斜是开环方向测试，不是姿态稳定。
当前完整方向表、运动渐变与验收边界见 `运动优化与方向核对_20261004.md`。

1. 先确认飞控上锁，停止本程序手柄控制；关闭QGC电机测试开关，取消QGC Joystick Enable。
2. 左侧编号按实际接线：左前1/右前2，左后3/右后4；垂推左前5/右前6，左后7/右后8。船头朝上。
3. 等飞控在线、映射核对通过。映射不符时禁止解锁，不自动修改参数。
4. 确认符合推进器厂家允许的空转条件。没有型号证据不能认定包住桨叶即可安全空转；需要水润滑的推进器按厂家要求浸水测试。
5. 勾选测试条件，点击“进入测试·请求解锁”。依次等待手动模式和已解锁的心跳确认。
6. 从低幅度开始，填写低侧/高侧PWM，点击对应“启动”按钮持续运行，再点任一测试按钮停止，不设固定运行时长上限。松开鼠标不停止；窗口失焦、切换编号/标签或编辑输入会发送1500µs中位。5%不转时可以逐步尝试10%、15%，不要直接拉满。岸上是否可空转及允许时长以推进器厂家要求为准，取消软件限时不代表允许无限空转。
7. 点击“停止测试并上锁”或Esc；等待飞控确认上锁后关闭面板。结束后保留11秒冷却。

正反向仅指PWM高于/低于1500µs，不是机身前进/后退，也不更改电机反转参数。测试幅度5/10/15%对应PWM偏移25/50/75µs；不是实测推力百分比。

“填入启转参考±50μs（不启动）”将单机及前进/后退/上升/下降两侧填为1450/1550。
这是可编辑的参考值，不保证每台已启转，不额外加50。点击填值先停止已有测试，再单独点击启动。
参考偏移可在controller_profile.json的thruster_startup.reference_offset_us设置0～100，重开程序生效。
前后组使用物理1～4，上下组使用5～8，按实际MOT_n_DIRECTION回传分配高低侧，其余中位。
仅有此测试快捷键不意味着正常手柄已经启用启转补偿；正常输出的飞控补丁见firmware/README.md。

面板显示实际PARAM_VALUE核对结果、COMMAND_ACK是否接受、SERVO_OUTPUT_RAW输出和最近飞控消息。
PWM回传不证明电机旋转；测试通过仍需人确认“哪一个转、方向是什么”。拒绝、无ACK、模式改变、链路失联或映射变化将停止并请求上锁；无法确认上锁时必须人工处理。

本实现参考当前固件提交的[ArduSub motors.cpp](https://github.com/ArduPilot/ardupilot/blob/dbe79216/ArduSub/motors.cpp)：固件不使用命令参数4的时长，而是500ms测试报文断流保护。应用已取消固定运行时长上限，仍保留再次点击/失焦停止、ACK超时和遥测异常停止；不把参数4当成安全计时器。

输入映射：物理1..8 → Motor2/1/4/3/6/5/8/7，命令209使用零基索引1/0/3/2/5/4/7/6。PWM类型1，BOARD顺序2。未选中的七路同时发送中位；AUX舵机不发送。

离线外观预览：`py -3 preview_motor_panel.py`（在此目录运行）。预览不打开UDP/HID/串口。
离线验证：`py -3 -m unittest discover -s pc_gamepad_bridge -p "test_*.py"`（在项目根目录运行）。
